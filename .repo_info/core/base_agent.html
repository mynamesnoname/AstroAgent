Constants — Error Keyword Groups

_CONNECTION_ERROR_KEYWORDS

_CONNECTION_ERROR_KEYWORDS = ( "connection reset", "connection refused", "remotedisconnected", "clientconnectorerror", "apiconnectionerror", "connect error", "network", "broken pipe", "eof occurred", "ssl" )

Connection-layer error keywords. Matches used by _is_connection_error to detect network-level failures that should trigger connection reset + retry.

_TIMEOUT_KEYWORDS

_TIMEOUT_KEYWORDS = ( "connectionerror", "connecttimeout", "timed out", "timeout", "readtimeout", "read timeout" )

Timeout error keywords. Matches used by _is_timeout_error to detect timeout conditions that should trigger wait + retry.

_RATE_LIMIT_KEYWORDS

_RATE_LIMIT_KEYWORDS = ( "rate limit", "insufficient_quota", "invalid_parameter_error", "function.arguments" )

API rate-limit / quota error keywords. Matches used by _is_retryable_error to detect throttling conditions.

Module-Level Functions

_is_connection_error

_is_connection_error(error_msg: str) -> bool

Check if an error message indicates a connection-layer failure (network drop, connection refused, SSL error, etc.). Triggers connection reset before retry.

→ True if any keyword in _CONNECTION_ERROR_KEYWORDS is found in error_msg.lower()

_is_timeout_error

_is_timeout_error(error_msg: str) -> bool

Check if an error message indicates a timeout condition. On timeout the retry loop waits and retries without resetting the connection.

→ True if any keyword in _TIMEOUT_KEYWORDS is found in error_msg.lower()

_is_retryable_error

_is_retryable_error(error_msg: str) -> bool

Check if an error message is retryable — i.e., it is a connection error, a timeout, or a rate-limit/quota error. Used as the single gate in the retry loop in call_llm_with_context.

→ True if _is_connection_error or _is_timeout_error or any keyword in _RATE_LIMIT_KEYWORDS matches

class BaseAgent

Abstract base class for all agents. Encapsulates LLM/VLM calls, auto-retry, error classification, thinking mode, skill loading with Jinja2 rendering.

Class variables:

FieldTypeDefaultDescription
agent_namestr"BaseAgent"Agent identifier for logging and dispatch.
_SKILL_DIRPath | NoneNoneDirectory for skill markdown files. Subclasses must set this.

__init__

__init__(self, runtime)

Initialize BaseAgent with a RuntimeContainer. Reads text and VLM model configs, detects vendors, sets thinking mode and streaming configuration.

Details:
self._text_model ← runtime.get_model("llm")
self._vis_model ← runtime.get_model("vlm") (lazy; None if VLM_API_KEY/MODEL/BASE_URL missing)
self._llm_thinking ← model config 'thinking' (default 'disabled')
self._vlm_thinking ← VLM config 'thinking' (default 'none')
self._llm_vendor / self._vlm_vendor ← auto-detected via _detect_vendor(base_url)
self._stream ← model config 'stream' (default False)

_skill_path

_skill_path(self, name: str) -> Path

Resolve a skill file path relative to _SKILL_DIR. If name has no extension, .md is appended automatically. Subclasses must set _SKILL_DIR.

→ Path pointing to the skill markdown file

_load_skill

_load_skill(self, name: str) -> str

Load a skill prompt template from file using _skill_path(name).read_text(encoding="utf-8").

→ Raw markdown string content

_apply_thinking

_apply_thinking(self, model, thinking_cfg: str, vendor: str, want_tools: bool)

Return a model with appropriate thinking extra_body bound. When thinking is 'none' or vendor is 'unknown', returns the model unchanged. When want_tools=True and thinking is 'enabled', forces to 'disabled' — multi-turn tool calls cannot pass back reasoning_content in LangGraph.

Logic: delegates to _build_thinking_extra_body(mode, vendor) and calls model.bind(extra_body=...) when override is needed.

_stream_invoke

_stream_invoke(self, model, messages)

Stream model output token-by-token via model.astream(messages), printing each chunk and accumulating the full content into a string. Returns the complete response.

→ str — full accumulated response content

call_llm_with_context

call_llm_with_context(self, system_prompt, user_prompt, image_path=None, parse_json=True, description="LLM output")

Core LLM call method. Assembles messages via create_message(system_prompt, user_prompt, image_path), selects text or VLM model, applies streaming if configured, and retries on retryable errors (connection, timeout, rate-limit).

Retry logic:
max_retries ← runtime.configs.max_tries (default 3)
retry_delay ← runtime.configs.retry_delay (default 180s)
Connection errors reset before retry; timeout and rate-limit errors wait and retry without reset. Non-retryable errors (e.g. auth failure, invalid request) are raised immediately.

JSON parsing (when parse_json=True):
1. Strip markdown fence markers (```json / ```)
2. Try json.loads()
3. Fallback: ast.literal_eval() for Python-style literals
4. If both fail, return the cleaned string as-is

→ Parsed JSON (dict/list) or raw string
Thinking-mode safety: When want_tools=True and thinking is enabled, _apply_thinking forces thinking to 'disabled'. This prevents the reasoning_content passback issue in LangGraph multi-turn tool calls, where the reasoning token block from a previous turn would be misinterpreted as the current turn's response.
